## 一、 大模型量化、微调与推理优化

### 1.1 显存为什么能从 14GB 压缩到 5.8GB？（显存精细计算）
* **Qwen2-7B 原始 FP16 显存**：
  * 模型权重参数量：$\approx 7.6 \times 10^9$ 个参数。
  * 每个 FP16 占 2 字节（Bytes）：$7.6 \times 2 = 15.2\text{ GB}$ 纯权重显存。
* **INT4 权重量化后**：
  * 每个权重仅占 0.5 字节（4 bits）：$7.6 \times 0.5 \approx 3.8\text{ GB}$。
  * 加上运行时激活值（Activation）、KV Cache 缓冲区和 PyTorch 上下文开销（约 1.5~2.0GB），总显存稳定在 **5.8GB 左右**。
  * **降幅计算**：$\frac{14 - 5.8}{14} \approx 58.5\%$。

### 1.2 主流量化算法原理对比
* **GPTQ (One-shot Post-Training Quantization)**：
  * 基于二阶泰勒展开（Hessian 矩阵），逐层最小化量化前后激活输出的均方误差：$\arg\min_{\hat{W}} \| W X - \hat{W} X \|_2^2$。
  * 优点：速度极快，7B 模型几分钟内完成量化，精度损失极小。
* **AWQ (Activation-aware Weight Quantization)**：
  * 观察到只有 1% 的显著权重（Salient Weights）决定了输出质量，通过统计激活值特征保护这 1% 的权重不被大幅量化误差破坏。
* **BitsAndBytes (NF4 - NormalFloat 4)**：
  * 假设预训练模型权重服从正态分布，将 16 个量化区间的概率面积严格等分，配合**双重量化 (Double Quantization)**（对量化常数本身再做一次量化，每参数再省 0.37 bits）。

### 1.3 QLoRA 微调核心机制
* **核心公式**：$W_{\text{finetuned}} = \text{dequantize}(W_{\text{NF4}}) + \frac{\alpha}{r} (A \cdot B)$
  * $W_{\text{NF4}}$ 保持冻结，只对低秩矩阵 $A \in \mathbb{R}^{d \times r}, B \in \mathbb{R}^{r \times k}$ ($r \ll d$) 进行梯度更新。
* **Paged Optimizers（分页优化器）**：
  * 类似操作系统虚拟内存的分页机制，当显存临时激增时，将优化器状态自动换出到 CPU 内存，避免 OOM 崩溃。

### 1.4 vLLM 推理加速核心：PagedAttention
* **传统推理痛点**：由于序列长度动态变化，传统推理必须预先按最大长度分配显存，导致 60%~80% 的显存碎片浪费。
* **PagedAttention 方案**：将 KV Cache 切分为固定大小的 Block（如 16 个 tokens 一个物理块），通过维护逻辑块到物理块的 Page Table，实现类似操作系统的非连续显存动态映射，显存利用率提升至 96%+，吞吐量提升 2~4 倍。

## 二、 边缘端计算与模型部署

### 2.1 TensorRT 核心优化原理
* **算子融合 (Layer & Tensor Fusion)**：
  * 将 `Conv + BatchNorm + ReLU` 融合为一个单一 GPU Kernel 执行，大幅减少中间特征图写回 Global Memory（显存）再读取的带宽浪费。
* **INT8 PTQ 校准 (Post-Training Calibration)**：
  * 通过 KL 散度（相对熵）最小化 FP32 激活分布与截断 INT8 激活分布之间的信息损失，确定量化缩放因子 $S = \frac{|T|}{127}$。
* **动态 Shape 与 Engine 固化**：
  * 针对特定硬件（如 Orin Nano 的 Ampere 架构）生成最优的硬件汇编执行文件（`.engine`）。

### 2.2 Jetson Orin Nano 达到 45+ FPS 的实战调优手段
1. **统一显存 (Unified Memory) 零拷贝**：Orin Nano 的 CPU 和 GPU 共享 LPDDR5 物理内存，利用 CUDA Zero-Copy 或 Unified Memory 消除 Host-to-Device 的 PCIe 传输瓶颈。
2. **CUDA Stream 异步双缓冲流水线**：
   * `Stream 1` 进行下一帧图像的预处理（Letterbox + 归一化 + NCHW 转换）；
   * `Stream 2` 执行当前帧的 TensorRT 推理；
   * `Stream 3` 执行上一帧后处理（NMS 目标框解码）。三者并发重叠。
3. **输入分辨率调优**：平衡 640x640 与 512x512，FP16 模式下单帧推理耗时从 38ms 降至 16ms。

## 三、 计算机视觉与目标检测

### 3.1 YOLOv8 与 YOLOv11 结构改进
* **骨干网 (Backbone)**：C2f 模块（v8）演进到 C3k2 与 C2PSA 模块（v11 引入空间注意力）。
* **检测头 (Head)**：采用 Anchor-Free 无锚框解耦头（Decoupled Head），将“分类任务 (Classification)”与“定位回归任务 (Regression/DFL)”在不同分支独立计算，消除分类与定位的特征冲突。

### 3.2 为什么需要 P2 高分辨率特征层？
* **传统 YOLO (P3-P5)**：最小特征图 P3 经历了 8 倍下采样（8x8 步长）。如果目标在原图中只有 $12 \times 12$ 像素，经过 8 倍下采样后只剩 $1.5 \times 1.5$ 像素，特征极易完全丢失。
* **引入 P2 层 (4 倍下采样)**：保留 $160 \times 160$（输入 640 时）的高分辨率浅层特征，保留丰富的边缘、纹理与位置几何细节，使得微小井盖、远距离违建等目标的召回率（Recall）大幅提升。

### 3.3 AMSFF (自适应多尺度特征融合) 原理
* 传统特征金字塔简单通过 Add 或 Concat 进行拼接，忽视了不同尺度特征的重要性差异。
* **AMSFF 方案**：引入空间自适应权重矩阵 $\alpha, \beta, \gamma$（满足 $\alpha + \beta + \gamma = 1$），让网络自主学习对当前小目标而言，深层语义与浅层细节的最佳融合比例。

### 3.4 单目测距数学原理（中电科 50 所项目）
* **针孔相机几何模型**：
  $$\frac{y}{Y} = \frac{f}{Z} \implies Z = \frac{f \cdot H}{h}$$
  * $f$ 为相机焦距（像素单位，由内参矩阵标定获得）；
  * $H$ 为现实中目标已知高度（如标准路灯高度）；
  * $h$ 为检测框在图像中的像素高度。
* **基于地面几何约束的俯角测距**：
  * 利用相机安装高度 $H_{\text{camera}}$ 与俯角 $\theta$，目标底部触地点在图像垂直坐标 $v$ 处：
  $$Z = \frac{H_{\text{camera}}}{\tan(\theta + \arctan(\frac{v - c_y}{f_y}))}$$

### 3.5 ReID 目标追踪与防重计数
* **ByteTrack / DeepSORT 结合**：
  * 提取目标检测框的外观特征向量（Embedding），与已有轨迹库计算余弦相似度；
  * 结合卡尔曼滤波（Kalman Filter）预测运动轨迹，通过匈牙利算法（Hungarian Algorithm）进行双重级联匹配，解决移动车载震动引起的重复计数与 ID Switch 漂移问题。

## 四、 RAG、Multi-Agent 与 AI-Native 工具链

### 4.1 RAG (检索增强生成) 核心链路
1. **文档切分 (Chunking)**：RecursiveCharacterTextSplitter（按段落/换行递归切分，设置 chunk_size=500, overlap=50）。
2. **向量索引 (Embedding & ChromaDB)**：基于 `text2vec` 或 `bge-large-zh` 将文本转化为 1024 维密集向量，存储于 ChromaDB 并建立 HNSW 索引。
3. **混合检索 (Hybrid Search)**：Dense Vector 余弦相似度 + BM25 稀疏关键词精确匹配。
4. **重排过滤 (Reranker)**：使用 Cross-Encoder（如 `bge-reranker-large`）对初筛 Top-20 进行打分截断，保留 Top-3 喂给 LLM。

### 4.2 Multi-Agent 4 层协同范式
* **Agent 1: 需求/日志解析 Agent**（将异构输入标准化为结构化 JSON Schema）；
* **Agent 2: 情报/知识检索 Agent**（调用向量数据库与搜索引擎获取上下文）；
* **Agent 3: 逻辑推理与交叉验证 Agent**（多轮 CoT 链式推理，识别因果关联）；
* **Agent 4: 交付报告生成 Agent**（排版渲染，格式审查与合规性检查）。
